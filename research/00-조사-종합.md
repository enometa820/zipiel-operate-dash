### 3-2. 현재 방식의 구조적 문제 (= 대시보드가 풀어야 할 진짜 과제)

전수 분석으로 드러난 데이터 품질 문제 — 이게 곧 대시보드의 가치 근거다:

1. **같은 데이터가 국가 탭마다 다른 스키마로 흩어짐.** KR=한국어 32열, JP=영어 31열, On-Air=영어 39열, SGP/US=28열(순서도 다름). 통합 조회·비교 불가.
2. **Status 값이 한·영 혼재.** `Email Sent`↔`컨택 완료`, `Dropped`↔`드랍`, `Content Published`↔(없음). 같은 의미가 탭마다 다른 라벨.
3. **Campaign 컬럼에 유형과 부가상태가 뒤섞임.** `Gifted`/`Paid`(캠페인 유형)와 `회신 없음`·`거절`·`무가협업`(진행 부가상태)이 한 컬럼에. 정규화 안 됨.
4. **상태 전이 이력(누가·언제·어느 단계→어느 단계)이 없음.** 현재 상태값만 덮어써짐 → "배송중→콘텐츠제작 며칠 걸렸나" 같은 리드타임 분석 불가.
5. **헤더행 위치·데이터 오염.** 헤더가 1~6행 제각각, Status 컬럼에 날짜값(`2026.04.21`)이 잘못 입력된 행 존재.
6. **성과 지표가 플랫폼별 별도 컬럼**(Likes IG/TR/TT/X/YT 분리) → 크리에이터·캠페인 단위 롤업(CPV 등)이 수기.
7. 과거엔 별도 봇(Armin)이 캡처 이미지에서 인플루언서명을 OCR로 긁어 붙이는 식으로 땜질 → 비효율.

## 4. 실제 상태 파이프라인 (운영 데이터에서 역추출한 enum)

effie가 정의한 15단계 + 시트 실제 Status 값을 종합한 **표준 상태 머신**(대시보드가 통일해야 할 정본):

| 페이즈(칸반 컬럼) | 표준 상태(영문) | 시트 실제 값(한·영 혼재) |
| --- | --- | --- |
| **1. Sourcing** | Listed → Contacted | Creator Listing / 리스트업 · DM · Email Sent / 컨택 완료 |
| **2. Negotiation** | In Discussion → Rate Inquiry → Confirmed | In Discussion / 협의 중 · 진행 확정 |
| **3. Contract & Fulfillment** | Contract → Shipping Info → Shipping | 계약서 · 배송정보요청 · Shipping / 배송 중 |
| **4. Content** | Guidelines Sent → In Production → Published | Guidelines Sent / 가이드라인 전달 · Content in Production · Content Published |
| **5. Payment** | Payment Pending (Gifted/PR은 스킵) | 지급 대기 |
| **6. Done** | Completed | completed · 협업 완료 |
| **(예외, 어느 단계서든)** | Dropped | Dropped / 드랍 |
| **(부가 태그)** | — | 회신 없음 · 거절 · 무가협업 · pr 박스 문의 · 후순위 (별도 필드로 분리해야 함) |

- **Campaign 유형**: `Gifted`(압도적 다수) · `Paid` · `Affiliate`(현재 시트엔 드묾, effie 요구엔 포함).
- **Tier**: Nano · Micro · Mid · Macro · Mega.
- **플랫폼**: Instagram · TikTok · X · Threads · 샤오홍슈(RED) · 도우인(중국은 텐센트 문서 별도 운영).
- **국가**: 말레이시아 · 싱가폴 · 대만 · 일본(+한국·홍콩·미국·중국 기존 데이터).

## 6. 데이터 모델 — `On-Air Sheet` 39컬럼 → 6테이블 정규화

`On-Air Sheet`가 가장 완성된 스키마(39 의미 컬럼)이며, 이를 정규화한 6테이블이 설계 토대다. (BP 검증 — 인플루언서 CRM은 "마스터 ↔ 캠페인 ↔ 협업(상태보유) ↔ 상태이력 ↔ 콘텐츠 ↔ 지급" 4~6계층 분리가 정석.)

| 테이블 | 담는 것 | 시트 출처 컬럼 |
| --- | --- | --- |
| `creators` (마스터) | 핸들·플랫폼·국가·팔로워·티어·이메일·담당자 — 한 번만 등록, 여러 캠페인 재참여 | Name · Account URL · Followers · Tier · Email · Platform · Country |
| `campaigns` | 캠페인명·유형(Gifted/Paid/Affiliate)·기간·예산·브랜드 | Campaign · Collaboration Brand |
| `collaborations` (조인+상태) | creator×campaign, **현재 상태 1개**·담당자·CPV·콘텐츠비용·컨펌·섭외맥락·물류 | Status · Manager · CPV · Content Fee · Confirmation · Source · Reason · Shipped Products · Tracking Number |
| `collaboration_status_history` (신규·시트엔 없음) | from→to·changed_by·changed_at·note — **리드타임 분석을 공짜로 줌** | (대시보드가 새로 추가하는 핵심 가치) |
| `content_pieces` | 게시물 URL·카테고리·게시일·성과(좋아요·댓글·조회·공유·저장 등) | Posted Product · Post URL · Original Video Link · Category · Likes/Comments/Views/… |
| `payments` | gross·tax·net·통화·환율·세율유형·지급상태 | Content Fee (KRW) + (세금 분기는 신규) |

**상태 머신 원칙**: 현재 상태는 `collaborations` 본체에, 전이 이력은 `collaboration_status_history`에 분리. 허용 전이만 가능(불법 점프 차단), 드랍은 어느 단계서든 가능한 예외 전이.

## 8. 지급·세금 처리 — 외국인 크리에이터 원천징수 (중요)

**핵심: 외국인 크리에이터에게 한국 프리랜서 3.3%를 일괄 적용하면 틀림.** 거주지·용역 수행 장소로 3갈래:

| 케이스 | 세율 | zipiel 해당 |
| --- | --- | --- |
| ① 한국 거주자(외국인 포함) | **3.3%** (사업소득) | 드묾 |
| ② 비거주자 + 용역을 한국 내 수행(국내원천소득) | **22%**(지방세 포함), 조세조약 제한세율 우선(예 10%) | 거의 없음 |
| ③ 비거주자 + 자국서 촬영·업로드(국외 수행) | **원천징수 없음 → 총액(gross) 지급** | **대부분 여기** |

→ zipiel의 말레이시아·싱가폴·대만·일본·중국 크리에이터는 **자국에서 콘텐츠 제작·업로드 = ③ → 한국 원천징수 의무 없음(전액 지급)**이 일반 원칙. effie 시트의 "3.3% 차감"은 한국 거주 케이스에나 맞음.
→ **데이터 모델**: `payments`에 세율 하드코딩 금지. `tax_type`(국내3.3% / 비거주-국내원천 / 비거주-국외수행=0%) 분기 + `gross·tax·net·통화·환율` 분리 컬럼.
→ 국가별 조세조약·실제 거주지 판정은 **회사 세무 담당/세무사 확인**이 정답. 대시보드는 "케이스를 구분해 담고 일괄 적용을 막는" 구조까지 책임.

근거 출처: 국세청 비거주자 원천징수 안내 / 벤처스퀘어 "외국 프리랜서 용역대가 원천징수" / 세무가이드 "비거주자 용역비 지급 서류" / 택슬리 "비거주자 사업소득 원천징수".

## 7. 대시보드 요구사항 — 충족 vs 갭

### 7.1 이미 충족 (우리가 만든 것이 푸는 것)
| 팀의 통증 | 우리 대시보드가 푸는 방식 |
|---|---|
| 시트 파편화·수식 붕괴 | 협업 1건 = DB 1행. shipping·on-air·status를 따로 옮겨적을 시트가 사라짐. 브랜드·국가별 뷰는 같은 데이터의 필터일 뿐 별도 시트가 아님 → 동기화 깨짐 소멸 |
| 동시편집 덮어쓰기·"ctrl+z" 수습 | server action 단일 DB write로 덮어쓰기 구조적 차단. 상태 전이는 `collaboration_status_history` append-only 트리거가 자동 기록 → "누가 언제 무엇을 바꿨나" 추적 |
| 상태를 슬랙 말머리로 추적 | `[In discussion]`·`[Collab confirm]`·`[Shipping]` 등이 곧 effie 시트 15상태에 1:1 매핑. 상태그룹 그리드가 "지금 어느 단계에 몇 건"을 자동 집계 |
| 다국어 팀의 상태 매핑 부담 | 상태 한영 병기 |
| 현 상태 분포 파악 | 좌측 사이드바 + 상태그룹 그리드 + 상세 패널 |

### 7.2 아직 갭 (팀이 매일 운영·보고하는 축인데 미충족)
명시 갭 7개가 코퍼스에서 모두 확인됨:

1. **캠페인 KPI 보드 (최우선·구조 갭)** — 운영 단위가 협업 1건이 아니라 "캠페인 = 브랜드 × 국가 × Dedicated/Integrated × 번호(목표·PIC·마감)". 14k 협업 카드 중심이라 캠페인 KPI(Target·Confirmed·CR·Remaining·D-day·PIC)가 한 화면에 없음.
2. **일일 보고 자동화 (최고가치)** — 전일 대비 델타·CR·잔여·역산 우선순위가 전부 수기. 우리는 이미 append-only 상태이력을 보유 → "전일 스냅샷 대비 증분"의 데이터 소스가 있음.
3. **배송 개수 추적** — Shipping을 단일 enum으로만 두면 in shipping / pending shipping / 발송완료 구분이 손실. 송장·carrier·수령마감일(여행) 필드 없음.
4. **쇼피 바우처 경로** — 실물 EMS와 분리된 풀필먼트(shopee_id·voucher_code·order_placed·receipt_paid)가 모델에 없음.
5. **국가별 집중제품·도입부 순서·제품비율 번들** — 1협업=1캠페인 모델이라 다브랜드·다제품 번들과 노출 순서를 못 담음.
6. **ratecard·CPV·유가/무가 정책** — Rate Inquiry 상태는 있으나 금액·통화·CPV·deal_type(gifted/paid) 필드 없음. 통화 정규화·브랜드 공유 뷰 vs 내부 뷰 분리 필요.
7. **업로드 후 성과지표** — `content_pieces` 테이블은 있으나 비어 있음(버그 아닌 시트 공백). post_url 기준 조회수·좋아요·댓글질·2차활용 수집·채움률 지표 필요.

추가 갭(중간 우선): **컨펌 승인 큐**(5스텝 체크리스트 게이트 + approval_status), **크리에이터 dedup·교차캠페인 플래그**(중복 배정 자동 감지), **이메일 확보율**(실질 컨택 모수), **미회신 경과일 stale 알림**, **콘텐츠 피드백 라운드 추적**(1라운드 초과 플래그).
